# Lite 的实际改动与证据边界

AUREL-Mem-Lite `2.0.0-lite` 是 AUREL-Mem 的写入策略变体。公开仓库名使用 `ARUEL-Mem-Lite`；这不改变模块名或服务协议。

## Add：按现有信息决定是否抽取

1. 对无图片的消息，原文直接作为索引摘要，不调用聊天模型；派生事实、实体、关系和状态数组保持为空。原文中的日期、说话者、短回复及尾部文字不因快路径而截断。
2. 对带图消息，只识别明确的 `Image Caption:` 标签及支持的拼写变体。单图接受唯一、非空 Caption；多图要求 Caption 位于对应图片前一个文字 part。仅有包装时间或标点的 Caption 不作为有效描述。
3. 明确对应的 Caption 直接用于图片索引，并记录 `caption_verified=false`。部分图有 Caption 时，仅未覆盖图片进入视觉调用；文字上下文仍可一起送入。归属有歧义时回退，不擅自把共享描述分配给所有图。
4. 模型回退沿用严格 JSON Schema、兼容网关的明确不支持回落、本地有限形状兼容和一次格式纠正。来源索引必须完整且唯一，空内容、错误状态字段或持续无效输出不能伪装成功。
5. 原始有序文字、图片和来源位置始终保存。`extraction_source` 标记 `raw_text`、`provided_caption`、`model` 或 `mixed`；这些是本地来源元数据，不由模型决定。
6. 开启 Embedding 时，每条消息仍建立向量。两种完全快路径直接嵌入原始文字；模型/混合路径使用原始文字加提取字段。请求 `text-embedding-v4` 的 1024 维输出，单条输入最多 8000 字符；完整原文留在 SQLite 和词法索引。
7. Add 所需的历史查询改为只读取同用户、同会话最近两条文字，保持先前上下文选择结果并避免扫描该用户全部历史。全部抽取和向量完成后，才在事务中提交请求与记录。

来自相邻消息的文字仅用于回退抽取时的有限上下文，不会把快路径图片重新作为图片上传。原始数据和图片出现记录不因文件内容相同而合并成同一条来源记录。

## Search：保留原检索算法和证据协议

`fusion_memory/retrieval.py` 沿用原版实现：原文、语义、视觉/OCR 三个 BM25 视角，与兼容的稠密向量排名进行加权 RRF；随后进行有界邻接扩展、时间处理、覆盖与冗余排序。Lite 没有加入新的检索模型或修改这些评分规则。

纯文本查询生成查询向量；图片查询先用 GPT-4o-mini 生成可见特征描述与检索词。选出的原始文字和图片按预算装入 `{data: [{id, content, score, created_at}]}`，供调用方回答模型使用。本服务不生成最终答案，也不选择选项。

代码相同并不意味着检索输入相同。快路径不生成额外实体和状态，原版依赖这些字段的某些匹配与扩展可能减少；提供的 Caption 也可能遗漏或写错图片细节。返回原图能帮助下游阅读已召回证据，但不能保证找回未进入候选集的记录。

## 如何理解贡献与测试

本变体的可核查变化是：在输入已经携带文字或明确 Caption 时减少重复的 GPT 抽取，同时保留来源映射、原始证据、向量索引、事务与原有检索协议。它是明确的工程取舍，不是对 Caption 路由、混合检索或记忆分层思想提出原创权主张。

单元和集成测试验证调用路径、序列化、持久化与回滚等行为。接口烟雾测试只能证明少量输入能跑通，不能证明质量等同原版、某个加速倍数或正式评测准确率。比较效果仍需固定数据、相同查询和配置下的完整评测及消融实验。

原始研究来源与未实现的部分见 [研究披露](research-disclosure.md)。
