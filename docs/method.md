# AUREL-Mem B / C 方法与实现

## 公共实现

- 已有 Image Caption 原样保存并建立分块索引；缺失时才由 gpt-4o-mini 补充。生成 Caption 的 OCR 和不确定描述会一起保留。
- 原始文字、每张图片的 Caption、解释图片的对话上下文、事件、事实和场景分别索引；v4 向量均规范化，稠密召回与 BM25 通过 RRF 融合。
- 图片像素按文件哈希保存，出现记录按消息/位置区分；同一图片不同会话的解释仍可保留，像素和相同 Caption 在交付时去重。
- MemCell 支持受约束的跨 Add 延续、版本递增、旧派生索引替换及原始版本留存。未延续的事件闭合；最新事件立即可检索，不等待会话结束。
- MemScene 按语义、实体与事件/长期主题范围归类。更新 Cell 时替换质心贡献；场景摘要由来源 Cell 重建，避免旧摘要递归漂移。首版不做复杂自动场景合并、拆分或全局实体同名合并。
- 状态变化、行为与偏好证据保留来源和时间，检索时按状态槽位/偏好维度扩展历史、代表行为和反例。单次行为不会被自动升级成稳定偏好画像。
- 原始时间戳转成可读时间供模型使用；没有依据的日期正规化被丢弃，保留原始时间短语，避免凭空补年份。
- 最多三轮搜索、两次 gpt-4o-mini 充分性判断。判断基于实际可交付证据，并最多查看两张原图；图像查询另有一次描述调用。没有新查询时可提前结束。
- 每轮最多八个原图候选，跨轮全局选择最多十二张原图；额外最多三十个 Caption/上下文包，其他相关文字使用剩余预算的最多 80%。这些数值都是上限，不会为填满容量加入无关内容。
- 按 117760 输入 token 预算预留问题、选项、查询图片和模板空间，图片计数使用保守可配置估计。较大图片可能使实际原图数少于十二；原始 Caption 不受旧版固定字符上限限制。极端长材料按命中的来源片段选取并显式标注省略，源库保留全文。

## 模型输出容错

使用 gpt-4o-mini 的 JSON object 模式，不强制巨大 JSON Schema。Prompt 明确说明字段可省略或为空，使用 M1/I1/C1/S1 等短 ID 降低来源引用错误。

本地依次完成 JSON/代码围栏/尾逗号修复、宽松字段归一化、短 ID 还原、父子来源补全、真实来源校验和原文回退。格式不符合要求不会触发第二次模型请求，`format_retry` 始终为 0。网络超时、429、部分 5xx 最多有一次传输重试；检索判断不做传输重试，失败照样消耗当次判断预算。

无法可靠提取的内容仍以原文、Caption 和来源 Cell 发布，记录 `extraction_fallback_cells`。这保证格式错误不使整次写入失效，但不代表结构提取在语义上绝对正确；回答证据始终携带原始来源。

## C 的重排

模型：[mlx-community/Qwen3-Reranker-4B-mxfp8](https://huggingface.co/mlx-community/Qwen3-Reranker-4B-mxfp8)，固定 revision `25f203a237b822a90f38763843562b93a5baf82f`。配置 `bits=8, mode=mxfp8, group_size=32`；这是 MXFP8，不称作 affine INT8。

采用 [Qwen 官方 Reranker 模板](https://huggingface.co/Qwen/Qwen3-Reranker-4B)的 yes/no 下一 token 分数，返回二者 logit 差作为排序依据；不做文本生成，也不把模型当 Embedding 使用。单例 MLX worker 串行执行，小批量为 1，输入最多 1024 token，避免同时装载多份 4B 权重。

每轮统一候选池最多 80 条；保留图片、直接文字与关系扩展的份额，未用额度可以回流。先针对原始问题评分，后两轮对最多 24 条补缺候选追加评分，最多 288 对/次 Search，缓存可减少实际计算。排序视图为 Caption/事实、解释上下文及来源片段预留各自空间，最终交付仍恢复完整证据。

重排异常、超时或非法分数时，本次 Search 后续使用 B 的排序，避免连续等待失败的重排。降级记入 `rerank_degraded` / `rerank_degraded_searches`，不能将降级请求当作正常 C 性能统计。
