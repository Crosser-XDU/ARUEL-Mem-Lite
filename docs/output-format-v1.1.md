# v1.1 抽取格式修复（历史记录）

本文记录原版 v1.1。Lite 仅在缺少 Caption 或 Caption 对应关系不明确的图片上复用该格式处理；当前版本为 `2.0.0-lite`。

v1.0 只要求模型返回 JSON，并在本地检查字段。v1.1 把接口结构约束与确定性兼容结合：先请求符合 JSON Schema 的结果，再将含义明确的表示差异规范化为内部格式，减少为格式问题重复调用模型。

## 接口约束

抽取调用使用官方 OpenAI Python SDK 的 Chat Completions：`response_format.type=json_schema`、`json_schema.strict=true`。Schema 要求固定字段类型、全部字段存在、当前批次的记录数量与编号范围；编号唯一性和来源完整性仍由本地检查。模型保持 `gpt-4o-mini`，向量模型保持 `text-embedding-v4`、`dimensions=1024`。

`EXTRACTION_OUTPUT_MODE` 支持：

| 值 | 行为 |
|---|---|
| `auto`（默认） | 优先严格 Schema；只有上游 400/422 明确表示不支持此格式时才退回 JSON 模式，结果仍需本地校验。能力结果在进程内缓存，并发初次请求只探测一次。 |
| `strict` | 要求上游接受严格 Schema，不自动降级。 |
| `json` | 使用 JSON 模式并执行同样的本地规范化和来源检查。 |

认证失败、限流、服务错误、网络异常、拒答、输出截断或 Schema 本身错误不会被当作“不支持格式”而降级。网关接受参数不等于证明它在所有请求上强制约束输出，因此本地校验继续保留。

## 本地兼容

- `index: "0"` 或 `0.0` 可转换为整数；布尔值、遗漏、重复、越界或数量不符仍拒绝。
- 字符串列表字段可接受单个字符串；`null` 转为空列表。列表中的数字、布尔值、对象与嵌套数组保留为完整的 JSON 文本，供索引检索，不自动转成事实状态。
- `summary: null` 转为空串；只有 `{"text": "..."}` 这种无歧义单字段对象可以解包。
- 完整的单个 `state_updates` 对象可包装成数组；显式数值与布尔值可转字符串。缺主体、谓词或值，以及不明确的复杂状态值仍拒绝，不能从任意关系对象推导状态。
- 可选字段缺失沿用空默认值；整条只有编号、空值、空容器或未知字段时仍拒绝，避免空记忆被当作抽取成功。

兼容操作不修改原文与原图，不补编号、不猜测来源、不补事实。返回记录可以乱序，但必须明确覆盖全部来源编号。

## 有界重试与诊断

本地可以规范化的结果直接使用，不再次调用模型。无法规范化时最多重新抽取一次；第二次提示包含固定错误类别、固定字段路径和要求的记录数量，不回放模型的错误原文。日志只记录安全分类和修复计数。

任一子批次最终失败时，取消并等待该 Add 其余尚未完成的子批次，减少失败请求遗留的上游调用。任何阶段失败都不提交部分记忆。SDK 自身的网络重试上限没有增加；未实现跨 HTTP 重试保存部分抽取结果，因此整批重试仍可能重新计算。

## 验证范围

使用独立模拟数据和隔离数据库验证，不读取评测正文、不重新加工评测图片。真实网关两组各 6 条模拟输入均一次通过严格格式调用，耗时约 7.54 秒和 7.63 秒；另一次图文 Add/Search 联调分别约 5.56 秒和 1.45 秒，幂等重试没有新增模型调用，原图完整回传且保存的向量均为 1024 维。

上述是少量链路测试，不能用于推断全量吞吐、失败率或赛事成绩。自动化测试覆盖兼容边界、并发回退、来源映射、空记录拒绝、全批原子性、幂等、鉴权与日志隐私。

## 适用范围

上述格式约束、兼容和重试逻辑由 Lite 的图片回退路径继承。纯文本及已有明确 Caption 的图片不进入 GPT 抽取流程。当前部署方式见根目录 README。
